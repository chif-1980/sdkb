# 运营与日常操作

本页面向知识管理员和内容审核人员，给出一套可以重复执行的日常工作方法。目标不是“让所有按钮都自动执行”，而是让系统先把资料、证据和风险整理好，人工只处理真正需要判断的部分。

## 日常工作闭环

```text
检查连接 → 增量扫描 → 观察进度与失败 → 处理运营待办
→ 审核知识单元 → 解决重复/冲突 → 发布并抽查
→ 查看处理记录 → 根据助手反馈复核
```

建议每天先看“运营待办”和高风险事项，再处理普通更新；每周抽查正式知识的引用、负责人和复核日期。

## 首次接入清单

1. 在“系统配置”确认飞书企业自建应用、回调地址和只读权限。
2. 在“知识加工”完成授权并点击“检查连接”。
3. 确认知识源根目录、权限范围和需要纳入的资料类型。
4. 首次执行一次全量扫描，等待扫描和资料加工阶段均结束。
5. 先处理解析失败和来源失效，再处理待审核内容。
6. 发布少量低风险知识，打开知识助手核对引用和回答，再扩大处理范围。

## 扫描操作

### 选择增量还是全量

| 场景 | 选择 | 原因 |
| --- | --- | --- |
| 日常同步飞书更新 | 增量扫描 | 只检查新增或版本变化，耗时和调用量较低 |
| 第一次接入 | 全量扫描 | 建立完整来源、版本和失效状态 |
| 调整目录或权限 | 全量扫描 | 重新核对整个配置范围 |
| 怀疑历史状态不一致 | 全量扫描 | 重新建立材料状态，但仍不会跳过审核 |

扫描启动后，页面顶部会显示阶段、百分比、当前资料和已发现数量。切换到其他菜单时进度仍会保留在全局状态；扫描期间可以查看已有资料，但审核、重建索引和跨文档补检等写操作会暂时停用，避免并行修改。

### 结果怎么看

- **新增/修改**：会进入解析和审核流程。
- **无业务变化**：若正文、图片、版式和知识单元均未变化，系统会提示可确认无需更新；`v0.2.0` 治理自动化的自动关闭仍需按部署阶段逐步开启。
- **来源失效**：先确认飞书目录、权限或移动情况，再执行下架确认。
- **加工失败**：系统先按 1、5、15 分钟重试；失败次数耗尽后，在运营待办中人工处理。

## 运营待办

“运营待办”不是另起一套任务，而是把现有对象聚合到一个入口。常见类型如下：

| 类型 | 优先级建议 | 进入方式 |
| --- | --- | --- |
| 待审核 | 按风险和超期排序 | 扫描发现新版本或新知识单元 |
| 来源更新 | 高 | 审核退回后飞书产生新版本 |
| 跨文档关系 | 冲突优先 | 检测到重复、重叠或冲突 |
| 加工失败 | 高 | 解析、索引或发布失败且重试耗尽 |
| 到期复核 | 高 | 正式知识达到复核日期或 30 天内到期 |
| 助手反馈 | 按影响范围 | 用户反馈可定位到正式知识 |

支持按负责人、类型、风险、状态和是否超期筛选。每条待办都应能看到 AI 摘要、建议动作、阻断原因和来源材料，点击后直接进入原处理页面。

## 审核工作区操作顺序

1. 先看质量门禁和影响摘要，判断是否存在硬性阻断。
2. 在左侧选择知识单元；“待处理”只显示尚未决定的单元，“已处理”用于复盘历史结果。
3. 在中间区域核对正文、页面/幻灯片/工作表定位和图片预览。
4. 在“跨文档证据”查看另一来源的实际重叠或冲突片段，不要只根据文件名相似下结论。
5. 选择处理结果并填写必要意见；按适用范围拆分时，至少填写一项范围且不能与另一侧重叠。
6. 提交后继续处理下一个单元。部分提交不会让整份任务消失；所有单元都有结果后任务才会完成。

### 批量操作边界

整篇批量审核和批量不纳入只作用于当前材料中尚未处理的知识单元，不会覆盖已经发布或已经逐项决定的单元。高风险、存在冲突或解析异常的任务应优先逐项处理。

## 跨文档重复与冲突

### 重复关系

- **保留来源一/来源二**：选择规范来源；重复侧不会继续作为独立正式知识，系统会留下别名或重复来源关系。
- **分别保留**：只有内容确实适用于不同范围时使用，并填写互斥的行业、产品、版本、部署方式或地区范围。
- 选择规范来源后，另一份材料若只包含重复片段且没有其他待决内容，相关审核项可以自动收口；若还有独有内容，独有知识单元仍需人工审批。

### 冲突关系

对于价格、版本、交付范围等事实冲突，不能用相似度自动决定。请按以下顺序处理：

1. 查看两侧原文、发布日期、适用范围和责任人。
2. 若候选版本已被业务确认，选择“采用新版”；旧侧会移出正式检索并记录替代事件。
3. 若当前正式版本仍有效，选择“保留当前版本”；候选侧不会发布。
4. 若两侧分别适用于不同范围，选择“按适用范围拆分”，填写互斥范围；系统拒绝范围重叠的提交。
5. 证据不足时选择“等待业务确认”或“退回来源修改”，不要用备注代替裁决。

## 正式知识维护

- **下架**：来源失效、内容过期或业务决定停止使用时，在正式知识中下架；原始记录和审计事件仍保留。
- **恢复**：确认来源和索引可用后恢复；恢复前检查活动版本和引用是否正确。
- **负责人/有效期**：修改负责人、有效期和复核时间会写入处理记录；到期知识进入运营待办。
- **重建索引**：只在索引损坏、模型切换或确认需要重建时执行；它不替代资料扫描和审核。

## 处理记录与通知

处理记录是完整业务审计时间线，不只记录跨文档事件，还包含扫描、解析、发布、退回、重试、下架、恢复、治理元数据修改和通知状态。跨文档裁决会关联双方资料，便于从任意一侧追溯。

系统提醒和飞书通知按部署阶段启用。观察阶段只记录通知意图；启用后，飞书投递失败不会回滚业务任务，而是记录失败原因并按幂等键重试。

## 助手反馈闭环

用户点踩时可选择“内容错误、内容过时、资料缺失、引用错误、其他”并补充说明。只有能定位到正式知识的问题才会生成治理待办；管理员应在待办中复核引用、来源版本和有效期，再决定下架、退回或创建修订任务。

## 常见问题排查

| 现象 | 先检查 | 正确做法 |
| --- | --- | --- |
| 资料队列分块显示为 0 | 审核包是否已生成知识单元、索引是否仍在排队 | 等待阶段性统计刷新；不要重复扫描 |
| 扫描时看不到进度 | 是否切换了菜单、浏览器是否仍是同一会话 | 回到知识加工页查看全局进度；必要时刷新页面 |
| 审核任务提交后仍存在 | 是否只处理了部分知识单元 | 这是预期行为，继续处理剩余单元 |
| 正式知识没有新内容 | 发布任务是否仍在处理或失败、单元是否选择纳入 | 查看发布状态和失败待办，不要重复提交 |
| 助手返回依据不足 | 资料是否已发布、来源是否有效、问题是否足够具体 | 先核对正式知识和引用，再补充关键词或来源 |
| 图片/版式预览失败 | 文件格式、解析状态、对象存储访问 | 先保留文字证据并重试解析；不要把预览失败当成正文为空 |

## 安全与回滚底线

- 不在聊天、截图或提交记录中记录飞书密钥、Token、Cookie 和对象存储凭据。
- 不通过直接改数据库的方式发布、下架或删除资料；优先使用管理端操作。
- 生产升级前记录当前版本和数据备份点；只重建应用服务，保留 PostgreSQL、Redis、MinIO、Milvus 数据卷。
- 出现新版本发布失败时，先确认旧活动版本仍可检索，再处理重试或回滚。
