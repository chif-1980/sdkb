# 产品概览

善达知枢是一套面向企业内部资料的知识管理与智能问答平台。它把分散在飞书和业务文档中的内容转化为经过人工确认、能够追溯来源的正式知识，再提供给知识助手使用。

系统的核心设计哲学是“来源优先、证据先行、AI 建议而非越权裁决”。AI 负责发现变化、归并知识单元、比较跨文档内容、计算质量分和整理待办；运营者负责核对原文、处理风险、确认发布。这样既能减少人工浏览和重复录入，又不会把待审核或无法追溯的内容直接暴露给问答用户。完整的边界和组件关系见[设计哲学与系统架构](/guide/architecture)，界面名词见[术语与状态定义](/guide/terminology)。

## 适合谁使用

| 角色 | 主要工作 |
| --- | --- |
| 知识管理员 | 连接资料源、执行扫描、处理失败任务、维护正式知识 |
| 内容审核人员 | 按知识单元核对正文、证据和版本差异，决定纳入、退回或不纳入 |
| 普通用户 | 通过知识助手查询已经发布的企业知识 |
| 系统管理员 | 配置模型、账号、权限、存储和部署环境 |

## 知识如何进入系统

善达知枢使用三个层级组织内容：

1. **原始材料**：飞书文档或上传的 Word、Excel、PDF、PPT、图片等文件。
2. **知识单元**：具有独立业务含义、适合人工判断和更新的一组内容，例如“公司简介”或“产品参数”。
3. **内容块**：用于检索、定位和引用的细粒度切片，通常不要求操作人员逐条管理。

原始材料负责保留完整来源，知识单元是主要审核和更新粒度，内容块负责让系统准确检索与定位。

## 标准工作流程

| 阶段 | 系统动作 | 人员动作 |
| --- | --- | --- |
| 资料接入 | 读取飞书目录和文件版本 | 确认知识源与扫描范围 |
| 内容加工 | 解析版式、识别知识单元、生成内容块 | 检查解析和定位是否准确 |
| 审核判断 | 提供正文、版本差异和跨文档证据 | 纳入、退回或不纳入 |
| 正式发布 | 将审核通过的知识写入正式知识库 | 抽查发布结果 |
| 知识问答 | 检索已发布知识并生成带引用回答 | 核对答案和来源 |

## 两种更新方式

- **局部更新**：材料只有部分内容变化时，只处理对应知识单元，其余已确认内容保持不变。
- **整篇更新**：材料结构或内容大幅变化时，使用整篇批量审核一次性处理全部知识单元。

系统保留原始材料与知识单元的关联，因此可以在不重复发布相同内容的前提下追踪后续版本。

## 会议如何推动后续工作

员工在企业知识助手调用 `@会议纪要`，提供分享链接、文字或转写文件。后台整理纪要、行动项和知识建议，员工可切换其他会话等待完成。

| 使用者 | 操作入口 | 负责内容 |
| --- | --- | --- |
| 上传者，即默认会议跟进负责人 | 助手对话中的“会议跟进” | 核对和补充待办、选择飞书企业成员、逐条确认发送，必要时修改原任务 |
| 任务负责人 | 飞书通知与待办 | 接收任务并推进执行，完成状态可回读到知枢 |
| 具有管理权限的知识维护人员 | 知枢“会议管理” | 查看本企业会议和待办，核对正式知识比对结果，处理知识更新建议 |

会议建议需经维护人员核对；新增或修改知识仍走原文维护、扫描、审核和发布流程。飞书登录共享身份，但管理权限须单独授予。详见[知枢使用手册](/guide/zhishu-manual)与[助手使用手册](/guide/knowledge-assistant)。
