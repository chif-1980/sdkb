# 善达知枢使用手册

面向知识管理员、审核人员和系统管理员，介绍从接入飞书资料到发布正式知识的完整操作。

**适用版本：0.6.0；核对日期：2026 年 9 月 20 日。** 本手册按 GitHub `sdkb` 当前版本编写。员工提问请阅读[企业知识助手使用手册](./knowledge-assistant)。部署、模型和登录配置见[部署与配置](../advanced/deployment)。

本手册沿用知识加工界面的演示截图，使用虚构演示数据；新增会议管理和统一登录按正文步骤说明。资料名称、数量和任务状态仅用于说明操作，不代表生产环境的业务资料或任务结果。点击截图可打开原图放大查看。

## 1. 功能架构与使用顺序

![善达知枢功能架构：飞书接入、扫描加工、审核治理、正式知识和助手反馈闭环](/images/manuals/zhishu-architecture.svg)

[下载架构图 SVG](/images/manuals/zhishu-architecture.svg) · [下载高清 PNG](/images/manuals/zhishu-architecture@2x.png)

**首次使用顺序：** 登录 → 添加数据源 → 管理员授权 → 检查连接 → 全量扫描 → 核对加工结果 → 审核 → 检查正式知识 → 到助手验证。

日常维护以增量扫描为主。扫描发现资料，加工生成可审核的知识单元，审核决定哪些内容进入正式知识；这几个阶段各有自己的状态。

| 使用者 | 主要工作 | 完成标准 |
| --- | --- | --- |
| 系统管理员 | 配置模型、飞书应用、登录与访问权限 | 服务可用，授权和连接检查成功 |
| 知识管理员 / 审核人员 | 接入资料、审核、处理重复冲突、维护正式知识 | 所负责单元有明确处理结果，发布可验证 |
| 来源维护人员 | 在飞书修改或补全被退回的资料 | 新版本经扫描进入复核 |
| 企业员工 | 在知识助手提问、核对来源和反馈 | 能找到有依据、符合适用条件的答案 |

## 2. 登录和认识工作台

使用管理员提供的**善达知枢地址**登录，进入左侧“知识加工”。看不到此菜单时，先核对账号是否具备管理员权限。员工使用的企业知识助手是另一个入口。

登录页支持**使用飞书账号登录**，与企业知识助手使用同一个飞书身份。首次扫码身份验证成功后，系统先登记用户，再检查管理权限；即使尚不能进入后台，管理员也能在「设置 → 用户管理」中找到该账号。列表分别显示“飞书账号：已关联／未关联”和“管理权限：已开通／未开通”。首次登录不会自动获得管理权限，需由有权管理该用户的管理员通过“编辑用户”授予管理员角色，再重新扫码登录。已有本地管理员账号仍可使用账号密码登录，不会按姓名自动与飞书账号合并。

登录后，在用户菜单进入**飞书账号与授权**，可查看当前关联身份、企业及系统角色。会议管理按该身份对应的企业和管理权限展示记录。飞书登录只完成身份认证，知识访问仍需具备相应授权。

页面顶部提供数据源切换、**数据源管理、检查连接、增量扫描、全量扫描**。展开数据源概览可查看链接、同步范围、授权身份和最近扫描时间。

| 页签 | 什么时候使用 |
| --- | --- |
| 审核任务 | 按资料查看待我处理、等资料、已转交、已完成的任务，审核知识单元 |
| 运营待办 | 集中处理失败、来源更新、关系问题、到期复核和可定位的助手反馈 |
| 跨文档检查 | 核对不同资料之间的重复、重叠或冲突证据 |
| 正式知识 | 查看发布结果，维护负责人、有效期、下架与恢复等 |
| 资料与扫描 | 查看素材队列、目录、扫描批次和加工状态，处理失败或重新加工 |

### 超级管理员与重新初始化

正常重启、重建应用容器或升级代码，只要保留原数据库，已有超级管理员及角色就会保留。系统已经初始化时会拒绝再次创建初始管理员。若删除数据库或改用全新数据库，账号和飞书关联不会自动迁移，需恢复备份或重新初始化；首次飞书登录不会自动授予超级管理员权限。

## 3. 添加飞书数据源

[![连接飞书知识库表单，默认自动创建同名知识库](/images/manuals/zhishu-source.png)](/images/manuals/zhishu-source.png)

1. 点击“数据源管理”，选择添加飞书数据源；没有数据源时也可使用页面空状态的添加入口。
2. 在飞书打开准备同步的知识库页面，复制浏览器链接，粘贴到“飞书知识库链接”。无需手工填写根节点 Token。
3. 按需填写数据源名称，并选择同步范围：**链接页面及下级内容**适合限定目录，**整个知识空间**适合接入完整空间。
4. 保持默认的“自动创建同名知识库”。系统在授权后读取飞书名称；如需汇入现有库，再展开“选择已有知识库”。
5. 点击“保存并授权”，系统先尝试复用当前飞书身份已有的知识访问授权，并核验企业身份和目标资料访问权。没有可复用授权时，由具有相应飞书访问权限的管理员完成扫码确认；二维码过期后重新生成。已有未授权数据源也可点击“复用我的飞书授权”。
6. 授权成功后查看连接检查结果，再开始首次全量扫描；若未自动完成检查，使用顶部“检查连接”。

**验收：** 数据源显示已授权、同步范围正确，连接检查成功，并且首次全量扫描可以启动。

::: tip 新建知识库的可见范围
自动创建的知识库默认仅创建者可见。要提供给其他成员使用，还需在知识库设置中配置共享和访问权限。授权成功不等于全部员工都获得了查看权，也不等于资料已经发布。
:::

授权失败时，先确认飞书应用已配置、回调地址与当前部署一致，且授权人可访问目标范围。迁移域名或服务器后，应用回调配置由系统管理员维护，普通用户不需要填写内部标识。重新授权会复用数据源，不要求重新创建知识库。

授权复用不会覆盖数据源已有的授权人。多个数据源共享同一凭据时，删除原授权数据源或更换其授权身份会使依赖它的复用授权失效，受影响数据源需重新授权。

## 4. 扫描、加工与进度

### 4.1 选对操作

| 操作 | 用途 | 不代表什么 |
| --- | --- | --- |
| 检查连接 | 验证授权、链接和同步范围可访问 | 不扫描、不解析、不发布 |
| 首次全量扫描 | 建立完整来源清单、安排新增资料加工 | 不自动通过审核 |
| 日常增量扫描 | 核对目录与版本，处理新增或变更资料 | 不是仅查看当前列表中的几行 |
| 再次全量扫描 | 全面核对来源状态、失效或范围变化 | **不强制重新加工所有未变更资料** |
| 重新加工 | 对符合条件的待审核素材重新解析、识别与检查 | 不覆盖已经作出的人工决定 |
| 重建索引 | 修复已审核内容的索引问题 | 不替代解析或审核 |

首次成功完成全量扫描后才能使用增量扫描。扫描期间部分写操作会暂时停用，待扫描完成并刷新状态后恢复。

### 4.2 在哪里看加工状态

进入“资料与扫描”，查看**扫描批次**的待加工、加工中、待审核和失败数量，再在**素材队列**按加工状态筛选具体资料。

[![资料与扫描中的批次统计和素材队列](/images/manuals/zhishu-scan.png)](/images/manuals/zhishu-scan.png)

| 状态 | 含义 | 下一步 |
| --- | --- | --- |
| 等待加工 / 待加工 | 已进入队列，等待后台服务领取 | 观察数量和更新时间是否变化 |
| 加工中 | 正在解析正文、图片或生成知识单元等 | 等待结果，避免重复提交 |
| 待审核 | 已产生需要审核的内容 | 进入审核任务；自动检查可能仍在进行 |
| 失败 | 某一加工步骤未完成 | 查看错误信息；可恢复失败会自动重试，必要时人工重试 |
| 不支持 | 当前正文加工链路不支持该来源类型 | 查看来源；音视频不按普通正文资料处理 |

扫描进度显示的是资料发现与安排加工的进度，不能当作“整批知识已发布”的百分比。批次内的“扫描、新增、变更”等是该次扫描结果；“待加工、加工中、待审核”等反映相关素材后续状态，处理完成后会变化。资料页会周期刷新，必要时点击刷新。

持续没有变化时，记录数据源、批次、素材名称、状态和时间交给管理员，检查后台加工服务和错误日志。**“检查中为 0”本身不能证明卡死**：可能尚未领取、已快速完成，或在等待其他任务，需结合等待数和更新时间判断。

### 4.3 为什么几个数量不一样

- **素材总数**按来源素材统计，并非知识单元数量。
- **待审核素材**按资料统计；审核任务还受当前人员、视图和筛选影响。
- **运营待办**包括审核以外的事项，与素材数量没有一一对应关系。
- **跨文档检查数量**表示已识别的关系，不表示所有等待检查的单元数。
- **正式知识数量**表示已发布内容；扫描、解析成功都不会直接增加正式知识。

对数字有疑问时，先统一数据源、筛选条件和刷新时间，再逐项对照具体资料，不把这些数字直接相加或要求它们相等。

### 4.4 重新加工已有素材

在“资料与扫描”的素材队列中选中符合条件的资料，执行“重新加工”；多份资料可使用批量操作，单次最多 100 份。系统从归档原文件重新解析，重建自动检查，完成后保持待审核。

此操作用于应用新的解析或装饰元素识别规则。已有人工审批或已发布片段的资料会被拒绝重加工，以保护原决定；应按提示走来源修订和新版本审核。加工失败用“重试”，索引问题用“重建索引”，不要混用。

装饰过滤针对透明或纯色图片、细分隔线、重复页边小图等低信息元素；带有效文字、图注或业务含义的图片仍需保留。不确定内容应结合原文核对，不能只按图片大小或文件名判断。

## 5. 审核知识单元

[![审核任务工作区：资料列表、正文证据与处理操作](/images/manuals/zhishu-review.png)](/images/manuals/zhishu-review.png)

### 5.1 单条审核

1. 进入“审核任务”，选择当前资料和待处理知识单元。
2. 查看原文、适用范围、AI 建议与待确认原因。知识单元是审批对象；正文片段用于定位，二者数量不一定相同。
3. 有跨文档关系时，打开证据，核对两侧原文；有来源更新时，核对版本差异。
4. 内容有效且需要提供给员工使用，选择纳入；无业务价值或不应进入库，选择不纳入；来源需修正，退回飞书修改。
5. 提交后查看已处理、待处理和纳入结果，再处理剩余单元。

**验收：** 当前单元有明确结果及记录。整份任务仍有其他单元时，会继续显示待处理，这是正常现象。

### 5.2 等待检查和需要人工确认的区别

“自动检查尚未完成”表示系统还没有形成最终检查结果，**不代表已发现内容风险**。页面提示等待、检查中或失败数量，并定时刷新；编辑过程中可能暂停刷新，也可点击“刷新状态”。

“待确认”则需要看具体原因，例如内容重叠、适用条件不明确、冲突或证据不足。不要只根据待处理总数判断风险。页码或定位与原文不符时，先核验原文并反馈定位问题，不凭错误页码确认重复。

### 5.3 整篇批量处理

当前资料中尚未处理的单元检查完成、满足条件时，可使用“整篇批量审核”；也可批量不纳入或退回。已处理单元不会被覆盖。

**不需要等待整个扫描批次的全部资料加工结束。** 但当前要处理的单元若仍在等待自动检查、存在冲突或质量阻断，应先按提示处理。整篇暂不能批量操作时，查看阻断原因和仍待处理单元，不要把“等待检查”理解为每一条都要人工认定有风险。

## 6. 处理重复与冲突

先对比匹配片段和来源，确认确实是业务内容重叠。装饰性图标、图片路径或相似文件名不能作为重复知识的依据。

| 选择 | 当前处理行为 | 仍需关注 |
| --- | --- | --- |
| 分别保留 | 两侧被匹配片段完整覆盖的待审知识单元会直接确认纳入 | 未完整覆盖或含其他内容的单元继续审核 |
| 保留来源一 / 来源二 | 选择规范来源，另一侧匹配片段记录为重复来源；满足条件的纯重复单元自动结束审核 | **所选规范来源仍需正常审批**；两边独有内容不受影响 |
| 等待业务确认 / 退回修改 | 证据不足或冲突需负责人确认 | 未解决的问题不应强行发布 |

这里的决定作用于界面列出的匹配范围，不意味着两篇文档的所有内容都已处理。提交后以实际处理结果及剩余单元数量为准；这也解释了为什么“重复关系已处理”后仍可能存在待处理知识。

事实冲突应核对日期、版本、产品和适用范围，再决定采用新版、保留当前版本或按适用范围拆分。相似度高低不能代替业务判断。详见[审核与发布](./review-and-publish)。

## 7. 发布验证与日常维护

审核提交后，进入“正式知识”确认发布成功，再使用有权限的员工账号到助手提问并打开引用核验。发布失败或仍在索引时，先检查状态和运营待办，不重复点击提交。

| 日常任务 | 操作建议 | 验证结果 |
| --- | --- | --- |
| 来源有更新 | 增量扫描，审核新版本 | 正式知识和引用版本符合预期 |
| 收到退回任务 | 在飞书修改，再扫描和复核 | 修改请求有记录，新版本进入审核 |
| 内容过期或来源失效 | 核验原因后下架 | 不再作为当前正式知识使用 |
| 恢复知识 | 核验来源、权限与索引，再恢复 | 有权限用户可检索并打开引用 |
| 收到助手反馈 | 在运营待办核对原回答和引用 | 完成复核、修订或下架并留下记录 |
| 日常巡检 | 查看失败、超期事项和负责人 | 需要人工处理的事项有责任人 |

来源更新但候选版本未审核时，不应直接取代上一版有效知识；最终是否可检索还取决于发布状态、来源有效性和用户权限。

## 8. 常见问题

| 现象 | 建议排查顺序 |
| --- | --- |
| 提示服务端连接失败 / 加载审核任务失败 | 刷新确认 → 检查登录状态 → 由管理员检查接口服务和日志；不是重新初始化系统 |
| 授权成功但不能扫描 | 检查连接结果、授权人访问权限和同步范围 |
| 一直等待加工或检查 | 核对批次、等待数、更新时间及失败信息，由管理员检查后台队列 |
| 整篇不能批量审核 | 区分检查未完成与真实风险，查看当前资料的具体阻断原因 |
| 重叠处理完仍有待处理 | 查看是否有独有内容、未完整匹配单元或规范来源仍待审批 |
| 原文页码或图片找不到 | 以实际原文件和有效定位为准，记录资料与片段交给管理员 |
| 正式知识有内容但员工查不到 | 核对知识库共享、用户权限、来源有效性和发布/索引状态 |

需要管理员协助时，提供页面名称、发生时间、资料标题、可见错误提示和操作步骤即可，避免在公开反馈中附带企业原文或登录凭据。


## 9. 其他管理功能与专题入口

本手册以知识接入、审核和发布为主线；平台还提供知识库、智能体与系统管理能力。具体入口受账号角色和部署配置影响。

| 需要做的事 | 操作指引 |
| --- | --- |
| 新建知识库、导入文件、设置访问范围 | [知识库与知识图谱](../intro/knowledge-base)，先确认知识库类型和索引模型，再添加资料 |
| 配置管理员工作区中的智能体 | [智能体配置](../agents/agents-config)，确认模型、提示词及可访问的知识与工具 |
| 配置对话模型和索引模型 | [模型配置](../intro/model-config)，保存后验证服务连通和实际调用 |
| 配置登录、系统参数和品牌 | [第三方登录](../advanced/third-party-auth)、[系统配置](../advanced/configuration)、[品牌自定义](../advanced/branding) |
| 检查部署与文档解析服务 | [生产部署](../advanced/deployment)、[文档解析](../advanced/document-processing) |

在知识库中直接导入文件，与飞书数据源的受治理发布流程是不同入口。需要供企业知识助手使用的内容，应按本手册完成适用的审核、发布和权限验证，不能仅以“文件已上传”作为验收依据。


## 10. 会议管理 {#meeting-management}

进入左侧 **会议管理**。当前入口需管理员权限；管理员关联有效飞书企业身份后，可查看和维护同一企业全部成员上传的会议，不同企业相互隔离。尚未关联有效飞书企业身份时，为兼容历史账号只显示本人会议。助手中的会议分析进入同一会议管理流程，无需再次上传；若列表为空，先检查当前企业范围、筛选条件和登录身份。

| 页签 | 用途 |
| --- | --- |
| 会议列表 | 按标题或纪要正文搜索、按分析状态筛选；分页查看并打开会议详情 |
| 待办跟进 | 跨会议查看待确认、已确认、已忽略、飞书同步异常和逾期事项 |
| 知识更新建议 | 汇总会议识别的知识建议，查看正式知识比对依据并记录维护决定 |

打开会议后，“纪要与依据”用于编辑正文、检索原文段落和导出 Word；“待办事项”用于补充或修改标题、内容、负责人、期限和执行状态；“知识建议”用于核对和保存处理说明；“处理记录”保留分析版本与修订记录。

**重跑与归档：** 重新分析失败时仍可查看上次成功的纪要和跟进结果；重新分析成功也会保留人工处理过的事项。相同标题不会自动合并，仅明确的重跑关联到同一会议。管理端归档独立于助手会话归档，不取消飞书任务；管理端归档后需恢复才能修改。助手会话已归档时，管理端可继续编辑已有纪要与待办；重新发起分析目前仍需先恢复原会话。

**待办信息：** “会议识别，待核对”表示从原文提取的姓名或期限，尚未作为正式分配确认；请在修改待办时选择企业通讯录人员并核对日期。纪要保留会议当时的安排，后续实际负责人、期限和进度以“待办事项”为准。切回后台或进入待办页会读取最新数据，编辑期间不会自动覆盖草稿。

**待办同步：** 保存修改只保存本地内容；点击“同步修改”后更新原飞书任务。负责人必须来自当前账号绑定的飞书企业通讯录，没有期限的待办不计入逾期。“已确认”表示人工已确认，不代表飞书已同步；请同时查看同步状态和错误说明。确认并发送时由飞书任务助手发送唯一通知，不再额外发送“sd知识库”机器人消息；日期按日期字段发送，知枢选择的截止日期与飞书显示日期一致。可点击“刷新飞书状态”读取完成情况，未同步的本地修改会被保留。当前管理端负责人下拉支持中文和英文姓名搜索；组织树和拼音筛选仍使用助手现有入口。

后台每轮结束后等待 5 分钟，再分批读取飞书任务完成状态，每批最多处理 20 场未归档会议；会议较多或飞书响应较慢时，更新会延后。在飞书完成任务后，助手与知枢会更新为“已完成”；重新打开后更新为“待开始”。身份失效、权限不足或读取超时时显示同步失败，保留上次有效状态，后续自动重试；需重新授权的情况请先处理授权。该回读仅同步完成状态，不回读在飞书直接修改的负责人、标题和期限。

**知识维护：** “已有知识覆盖”需选择当前有效、已发布的正式知识并填写依据。需要修改已有正式知识时，选择“提交原文修改审核”，填写修改建议并关联正式知识；系统会创建现有来源修改审核任务，通知维护人员修改飞书原文，后续按现有扫描、审核和发布流程处理。需要新增知识时先选择“待补回原文”，由维护人员补回飞书原文后再启动治理流程；暂缓和不采纳均保留处理说明。会议管理不会直接发布正式知识。

顶部指标与列表采用相同的可见范围。待确认和逾期事项、待核对知识建议及分析异常均可点击进入对应列表；已归档会议不计入这些工作指标。
