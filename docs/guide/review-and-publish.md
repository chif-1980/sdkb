# 审核与发布

审核的主要对象是知识单元，不是细碎的内容块。内容块用于在原文中定位和引用，知识单元才是操作人员确认、更新和发布的业务内容。

## 局部审核

材料只更新一部分时，在右侧审核信息中处理当前知识单元：

1. 选择需要核对的知识单元。
2. 查看原文版式中的定位内容。
3. 核对跨文档证据和版本差异。
4. 选择处理结果。
5. 切换到下一知识单元继续处理。

已处理单元会保留结果，未处理单元仍留在“待我处理”，不会因为提交部分结果而消失。

“已处理”入口用于复盘已提交结果；已提交发布、已处理（未发布）或已结束修改任务的单元不能再次重复提交。审核包只有在全部知识单元都有最终结果后才会进入“已完成”；部分提交不会误关闭整份任务。

## 整篇批量审核

整篇材料内容一致、风险可控且无需逐项判断时，可以使用批量操作：

- **整篇批量审核**：将所有待处理知识单元纳入知识库。
- **批量不纳入**：将所有待处理知识单元标记为不进入知识库。
- **批量退回**：将所有待处理知识单元退回飞书修改。

批量操作只作用于当前材料中尚未处理的知识单元，不覆盖已经逐项确认的结果。

对存在冲突、证据不足或解析异常的单元，批量按钮会缩小可操作范围或直接禁用，应回到单元级处理。批量操作提交后仍要检查“已处理/待处理/已纳入/不纳入”计数。

## 处理结果

### 纳入知识库

内容有效、来源可靠且需要提供给知识助手使用时选择此项。任务完成后，系统会发布为正式知识。

### 不纳入知识库

内容无需进入知识库、与已有正式知识重复或不属于当前知识范围时选择此项。该结果表示已经完成判断，不是审核失败。

### 退回飞书修改

内容存在事实错误、表述不完整、版本不明确或版式解析问题，需要来源维护人员修改时选择此项。

“问题标签”仅在退回飞书修改时使用，用于说明修改方向；审核意见可选填。

### 质量门禁

审核包详情会显示质量门禁、五个评分维度和影响摘要。综合分为 100 分：证据与可追溯性 30 分、内容完整性 25 分、一致性与重复冲突 20 分、时效性与有效期 15 分、责任人/分类等治理元数据 10 分。

- `80–100`：建议通过，但仍需人工确认。
- `60–79`：需要重点人工复核。
- `<60`：建议退回处理。
- **质量门禁阻断**：正文为空或解析不完整、缺少来源定位、存在未解决冲突、来源失效/无法核验时，分数不能抵消阻断，禁止发布。

影响摘要会分别标出正文、图片、版式是否变化、受影响知识单元数和未处理关系数。“符合自动关闭条件”只表示满足安全条件；当前观察阶段不会自动关闭，启用自动化后也只处理无业务变化、无冲突且解析完整的候选版本。

## 如何核对证据

审核工作区提供三类信息：

- **当前正文**：当前材料中的原始内容和版式位置。
- **跨文档证据**：其他材料或正式知识中可能重叠的内容。
- **处理记录**：该材料和知识单元之前发生过的审核、发布与退回动作。

版式对比时，两侧可以独立翻页。证据位于不同页时，无需强制同步页码，以高亮文字和来源定位是否对应为准。

## 多格式版式还原

| 文件类型 | 核对方式 |
| --- | --- |
| PPT | 按页还原版式，同页内容块可点选定位 |
| Word | 按页面和段落还原，保留标题、表格和图片位置 |
| Excel | 按工作表和可视区域展示，支持缩放与定位 |
| PDF | 按原始页展示并叠加文字定位 |
| 图片 | 显示压缩预览，并将 OCR 文字映射到原图位置 |
| Markdown | 按标题、段落、列表、表格和代码块定位，不强行伪造页码 |

大图片和复杂页面会使用适合审核的预览分辨率，原始文件仍作为最终来源保留。

## 提交后的去向

- 仍有未处理知识单元：任务继续留在“待我处理”。
- 全部选择不纳入：任务进入“已完成”，正式知识中不会新增内容。
- 全部完成且至少一项纳入：发布成功后可在“正式知识”查看。
- 选择退回：任务等待飞书来源更新后重新扫描。

### 处理重复与冲突

重复关系提供“保留来源一”“保留来源二”“分别保留”三个选择：选择规范来源后，另一侧重复片段会记录为重复来源；若另一侧知识单元还包含独有内容，独有单元仍须审批；“分别保留”要求两侧适用范围确实不同，并且两边仍独立审批。完全由重复片段组成且没有其他未决关系的单元，系统可自动收口并在记录中标明原因。

冲突关系不能只按相似度决定。对于价格、版本、交付范围等冲突，先核对原文日期、适用范围和责任人，再选择“采用新版”“保留当前版本”或“按适用范围拆分”；两侧都是候选版本时不能凭空选择“保留当前版本”，应采用新版或等待业务确认。未解决冲突会持续阻断发布。

### 完整业务审计

“处理记录”是追加式业务审计时间线，包含扫描、解析、审核、发布、退回、跨文档裁决、下架/恢复、重试、转交、资料修改请求和治理元数据变更。每条记录尽量展示资料标题、版本、操作人、状态变化、前后字段和关联对象；跨文档事件会同时关联双方资料。

提交后暂时看不到正式知识时，不要重复操作，先检查发布状态和失败信息。
